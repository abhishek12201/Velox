# P8 · Memory across sessions
Model: cheap · Time: 2h · Needs: p7
Read: spec §8, §11 (S5).
Build:
- Inject compact profile into the system prompt each turn (<=300 tokens, from `vault.get_profile`). Emit `chip` events when `remember` is called ("Remembered: avoids flights before 07:00").
- Prompt rules: call `remember` on stated preferences and when the user rejects an option with a reason (source inferred + evidence = the user's words).
- "Same as last time": the model uses `list_trips` + profile; make sure the mock scenario and prompt support "same as last Goa trip, my sister is coming" (pax from 1 to 2, budget recalculated by asking once if unclear).
- `scripts/seed-demo.ts` + `npm run seed:demo`: writes one past trip and two profile entries to the vault DB; `scripts/reset.ts` + `npm run reset` clears all data dirs.
- `/api/reset {scope:"session"}` keeps the vault; `{scope:"all"}` wipes it.
Accept: e2e S5: session A states a preference and confirms a trip; session B (new session id, same vault) plans using them and emits the chip; a reset(session) test proves the vault survives.
Know-it: 1) what is stored where and why in the vault server 2) how inferred preferences stay explainable
